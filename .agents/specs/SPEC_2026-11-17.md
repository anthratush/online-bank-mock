# SPEC_2026-11-17 — Session Learnings: Online Bank Mock

## Project Context

- **Stack**: SvelteKit 2 + Svelte 5 (runes mode), TypeScript, TailwindCSS, npm
- **Storage**: `localStorage` key `"user"` → `{ account, currencies, transactions, isAuth }`
- **Data model** (`src/lib/utils/storage.ts`):
  - `Currency`: `{ id, name, symbol, cardBalance, cardNumber, cardCVV, cardExpDate }`
  - `Transaction`: `{ uid, name, date, amount, currency, type: 'debit' | 'credit' }`
  - `UserAccount`: `{ firstName, lastName, pinCode, country, phone, email }`

## Key Learnings

### 1. Transaction `type` semantics (evolved during session)

- Added `type: 'debit' | 'credit'` to `Transaction`
- **Final semantics (swapped mid-session)**: `debit` = income (money in, green, `+`), `credit` = expense (money out, red, `-`)
- **Amount stored as absolute value**; sign is derived from `type`, never from the amount's own sign
- Legacy fallback: `transaction.type ?? (amount < 0 ? 'credit' : 'debit')`

### 2. Svelte 5 runes patterns

- Use `$state`, `$derived`, `{@const}` inside `{#each}` — **never** legacy `$:` reactive statements
- Read `localStorage` in `onMount()`, NOT in `$effect` — avoids SSR hydration mismatch and clears `svelte-autofixer` suggestions about state-in-`$effect`
- `svelte-autofixer` flags unused CSS selectors targeting child component roots — use Tailwind arbitrary variants like `[&>*]:shrink-0` instead

### 3. Admin page patterns

All admin pages follow the same structure:
- Wrapper: `min-h-screen bg-gray-50 p-6` → card: `mx-auto max-w-md rounded-lg bg-white p-6 shadow-md`
- Indigo primary buttons, gray cancel buttons, inline red error text with `aria-invalid`/`aria-describedby`
- Load via `getUserData()` in `onMount`, save via `saveUserData()`
- `resolve()` from `$app/paths` for links, `goto()` from `$app/navigation` for programmatic nav
- Admin panel (`+layout.svelte`) opens via 5-tap on account icon; each admin route needs a link there
